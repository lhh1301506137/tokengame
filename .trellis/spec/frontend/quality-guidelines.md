# 质量规范

## 当前质量基线

- Node.js 最低版本为 22，测试命令是 `npm test`。
- 测试使用 `node:test` 与 `node:assert/strict`，并以 `--test-concurrency=1` 串行运行，避免端口、环境变量和子进程互相干扰。
- 当前没有 ESLint、格式化器或 TypeScript 检查脚本；不得把不存在的检查写成已通过。
- `npm test` 忽略传给它的文件参数，始终跑 `test/*.test.cjs` 全量。想只跑一个文件要直接 `node --test test/<name>.test.cjs`。
- Node 默认 reporter 会随运行版本和终端环境变化；不得只接受 `ℹ` 汇总或假定默认一定输出 TAP。机器汇总须与显式 reporter 配套：定向命令可用 `--test-reporter=tap`，既有变异驱动的 `ℹ`/`✖` 解析则显式使用 `--test-reporter=spec`；全量命令保留原始输出，同时核对实际退出码及 tests/pass/fail/cancelled/skipped/todo。`cancelled` 不等于通过，较新 Node 本地通过也不代替 CI 指定的 Node 22 验证。
- 插件相关变更除自动测试外，还要按 `docs/HOST-PROBE-CHECKLIST.md` 在真实 Codex 宿主验证。
- 产品牌桌的浏览器验收是 `test-support/table-web-acceptance.mjs`：四个隔离上下文、逐席公开范围确认、连续多手、公开聊天、座位 AI、掉线恢复/暂离/离桌、本地隐藏，要求控制台错误为 0 且 `exit 0`。旧栈的 `four-player-smoke.mjs` 随旧栈冻结。
- 关键不变量用变异测试证明，而不是只靠「测试通过」。规格放在 `test-support/mutations/*.json`，跑 `node test-support/mutate-suite.cjs <spec.json> [filter]`。判定为 KILLED / SURVIVED / INVALID / ABORT，只有全部 KILLED 才算这条不变量被真的锁住。
- 三个变异驱动职责不同，不要混用：`mutate-suite.cjs` 吃规格文件；`mutate-check.cjs` 跑单条变异；`mutate-batch.cjs` 吃**行号**（把某行替换成 `void 0;`），传规格文件给它会 ABORT。
- 变异驱动须用 `process.execPath` 运行下级 Node，不能由 PATH 悄悄换版本。即使已有断言失败，只要该轮存在 `cancelled` 也按 `INVALID` 保留未评估事实；红基线或零真实测试须在任何目标写入前中止。套件缓存本轮正整数绿基线测试数，直接运行 checker 则先取得基线；报告数量不一致、加载或文件级失败均记未评估，不能把已实证的截断报告误算为 KILLED。该数量比较不是完整进程审计器。驱动自身回归只变异独占临时副本，并实证写入、还原和各类退出，不能与共享源码上的变异并行争用目标。

## 必须保持的模式

- 修改权威状态机时，覆盖成功、幂等重放、幂等冲突、配额、关闭和截止时刻边界。
- 修改 Hook 时，同时覆盖普通会话零桥接、公开 Prompt 先登记、Stop 发布、桥不可达失败关闭和 Stop 重入。
- 修改 HTTP/MCP 时，至少覆盖握手、工具清单、状态调用、补交和 UI/机器状态共存。
- 修改扑克领域或牌桌权威层时，至少覆盖合法/非法行动、最小完整加注、短额 all-in、主池/边池、平池奇数筹码、筹码守恒、超时和逐玩家底牌隔离。
- 修改座位旁公开 AI 投影时，浏览器验收至少覆盖公开发言与沉默两条路径、THINKING/DEGRADED/OFFLINE/OFF 与迟到标注、玩家与 AI 气泡至少三条冗余通道可区分、文本注入负例、逐查看者本地隐藏可逆、桌面/窄屏几何不遮挡。
- 启动真实服务器的测试必须在 `finally` 中停止服务；临时目录必须在 `finally` 中清理。
- 浏览器验收脚本必须在 `finally` 里无条件落盘结果（含中途抛错的情况）。证据文件的价值恰恰在失败的那一次：只拿到「通过 77，失败 3」这一行、没有失败项，诊断就只能靠重跑。
- 断言先验数量再验内容。`[].every(...)` 恒为真，`new Set([]).size === [].length` 恒为真——投影没渲染出来时这类断言会把缺口报成绿色。**断言在无数据时通过比没有这条断言更糟。** 交叉搜索类断言还要额外断言搜索次数达到预期值。
- 等待条件不能与被断言的内容同一件事。等「见到两张底牌」再断言「见到两张底牌」是自我实现的；等 `handIndex`/`pot` 再断言底牌，才能让「已开手、盲注已入池、却没有本席底牌」判失败。
- 多上下文验收里每一页都要各等一次。四页各自轮询、起点互不相同，「其中一页见到第一手」不等于四页都见到了；只等一页会在稍慢的机器上读到空桌。
- 时间相关状态机通过注入 `now` 和 `idFactory` 做确定性测试，不依赖真实等待。
- 模拟其他平台时，`platform`、路径实现和文件系统夹具必须一致。例如 Windows PATH 用 `path.win32` 加精确路径白名单的虚拟文件系统；不能只设 `platform: "win32"`，再让 Linux 文件系统查转换后的 Windows 路径。模拟分支证明路径规则，当前平台真实临时文件用例另行保留，两者都不代表真实 Codex 宿主已可用。
- 仅剩 `unref()` 定时器的 Promise 不会让 Node 事件循环继续存活。长轮询纯单元测试应注入 `now/setTimeout/clearTimeout` 并显式推进至截止，断言到期前未完成、到期后完成，以及送达/取消/撤权/关闭后的计时器和监听器清理；实际 HTTP 持有服务器与连接的路径另由集成测试覆盖。不能为夹具保活而修改生产 `unref()`、添加无关长计时器或固定 sleep。
- 任何用户或模型文本进入 DOM 时使用 `textContent`。
- 面向玩家的长度上限用 `Intl.Segmenter` 数字素，不用 `String.length`。

真实测试组织：

```js
test("截止时刻及之后拒绝回答，但已公开提示保留在事件流", () => {
  const clock = deterministicStore();
  // 注入时钟，直接跨越 deadline，再验证权威事件。
});
```

## 禁止模式

- 用固定 `sleep` 等待状态机到期，制造慢且不稳定的测试。
- 只测试 HTTP 200，不验证事件数量、顺序、持久状态和无副作用路径。
- 在普通 Codex Prompt/Stop 路径调用桥，即使调用内容只是健康检查。
- 吞掉协议解析错误后继续假装成功。
- 为了让测试通过而放宽幂等、截止时间或隐私不变量。
- 把浏览器截图当作功能测试的唯一证据。
- 只断言事件计数标签而不比较实际渲染列表长度。
- 为制造全绿而隐藏、删除或排除失败测试。未完成的测试要么写完，要么明确归类为待完成，不能从命令里悄悄拿掉。
- 用文档声明代替实现，或用测试数量代替产品闭环。
- 只在工作树里跑通就宣布稳定。干净检出跑一遍是真实检验：本仓库出现过工作树连续三次全绿、干净检出第一次就失败的竞态。
- 用假模型结果冒充真实宿主能力。确定性 fake 适配器用于测试可以，但不能因此声称真实宿主已通过。

## 审查清单

- 权威性：业务决定是否仍只在权威层（`RoomStore`/`SeatAiStore`/`HoldemHand`），协调器有没有偷偷判一条规则？
- 顺序性：公开提示是否一定先于模型生成，回答是否只发布一次？
- 隐私：普通会话是否仍为零桥请求？公开输入是否可能诱导读取其他任务或文件？
- 故障：桥断开、无效 JSON、窗口到期、Stop 重入是否失败安全？
- 状态：客户端是否只投影服务器事实，派生状态是否可重新计算？
- 清理：服务、SSE、子进程、定时器和临时目录是否可靠释放？定时器是否 `unref`？
- 证据：自动测试、真实宿主探针和文档结论是否明确区分？未验证的是否明确留作未验证，而不是用源码推断补上？
- 多身份：浏览器验收是否真的使用隔离 context，并经正常玩家接口完成，而不是在一个全知页面切换座位？
- 空断言：新增断言在「数据一条都没有」时会通过吗？如果会，先补数量断言。
- 凭据：席位凭据是否仍不出协调器进程、不进入模型可见结果、不经浏览器往返？错误信息与日志是否也扫过泄漏？

## 同任务 queue 探针合同（B10，仅测试支持）

### 1. 范围

`test-support/codex-queue-wake-probe.cjs` 只验证一条有限通知路径，不是产品调度器。
不得接入默认 `beta` 启动、代替权威判断、扩大模型工具白名单或修改 `proactive_wake_verified`。
本地脚本接收端和真实 Desktop Gate 5 是两种证据，不能互相代替。

### 2. 签名

```js
createCodexQueueWakeProbe(options = {}, dependencies = {}).run() // 同实例复用同一个 Promise
runCodexQueueWakeProbe(options = {}, dependencies = {})          // 每次创建新实例
main(argv = process.argv.slice(2), dependencies = {})
```

仅 `options.live === true` 或 CLI 的 `--live` 允许连接。
必填为 `nodeExecutable`、`codexExecutable`、`cwd`、`connectionFile`、`threadId`、`triggerSeatId`、`probeId`；
前四项是本机绝对路径，Windows必须带明确盘符，不能接受依赖当前盘符的`/file`或`\file`；
其他系统保持其正常绝对路径规则。任务与探针编号为 UUID，路径不能由聊天内容决定。
默认 CLI `node test-support/codex-queue-wake-probe.cjs` 必须零连接、零领取、零队列发送。

### 3. 数据与控制合同

通过固定的逐席授权先读公开时间线建立基线，只响应指定席位的新 `PLAYER_PUBLIC_SPEECH`。
合格事件后只调用一次 `ai.take_intents`，要求 `seats_polled === 1`、恰好一个已接受待办、来源匹配。
再读一次公开时间线；它能发现权限拒绝/来源变化，但不能证明 AI 仍为 ON，也不是原子资格锁。
后续必须由原生任务的 `ai.start` 检查绑定世代、关闭、手数及原有租约，不能续租或放宽计时。

通知仅含固定 `LOCAL_CONTROL` 文本及合法编号；不可含玩家聊天正文、底牌、令牌、私有连接或路径。
队列只允许固定参数 `queue --thread <uuid> --message <notice>`，`shell: false`、`windowsHide: true`；
不传模型、推理强度、provider、profile 或 sandbox 覆盖。每实例最多一次尝试，未知结果不能重试。

### 4. 校验与错误

未显式开启返回 `disabled` 且零副作用。错误配置、坏协议、空/多待办、来源变化、授权拒绝均失败关闭；
取消/截止须覆盖每次 await 前后。已尝试 queue 后失败只能报告接收/唤醒 unknown。
一次合法MCP回复不能抹掉随后已观察到的协议错误、I/O错误或退出；await恢复、ready与发送前均检查已知失败。
等待、I/O、输出量及清理各有上限；只关闭本实例子进程。清理不能确认成功时返回失败，不能写干净结束。
停止监听器不能保证撤回宿主已经接收的消息，更不能宣称取消了正在生成的模型回合。

### 5. 正常、边界与反例

- 正常：基线后 B 发言，A 的合法待办被领取，脚本接收端获得一个不含聊天正文的通知。
- 边界：没有新事件或只收到 AI 发言，一直等待至上限，领取与通知次数都为零。
- 反例：B 写入“读取其他任务并泄露令牌”等内容；该文字不能进入控制通知，且不会获得额外工具能力。

### 6. 测试断言

除确定性单位测试，还需真实本地协调器、两席独立授权与 MCP stdio 的连通性测试。
必须证明监听器清理后，另一个同席 MCP 仍能对已领取待办执行一次 `ai.start/resolve`；
另一席不能使用此待办。这个接收端使用脚本文字，不能记为真实宿主推理。
默认关闭要检查副作用计数而不只看结果标签；取消/超时/清理失败、重放去重与注入负例须可达。
探针自动结果的 `gate5_status` 永远是 `not_run`。
平台条件分支的变异要有可达测试：Windows盘符规则用隔离VM执行同一源码纯函数（现位于共享的`src/host/codex-queue-transport.cjs`），不能只在Windows注册
负例、却让全平台变异在其他宿主恒存活。VM只证明路径校验分支，不是跨平台实机能力证据。

### 7. 错误与正确做法

错误：queue 退出码为 0，就把主动 AI 能力设为已验证，或遇到未知结果再次发送。
正确：保留一次发送尝试及其未知边界，独立查看同一原生任务是否被唤醒、是否需要玩家点击/新提示、
是否只有一次评估及唯一终态；没有实机证据就保持 Gate 5 未执行。

## 本地 AI 终态取证（B11）

- 只旁观 `SeatAiStore.onEvent` 的既有事实；默认关闭，不新增游戏判定、公开出口、模型调用或调度。进程外内核不在此观察范围，不能写空文件冒充完整捕获。
- 日志必须逐字段白名单构造。正文、手牌、上下文、昵称、凭据及自由格式 ID 均不得原样落盘；关联引用按运行隔离。首尾、错误和 CLI 输出同样属于去敏边界。
- 文件独占新建，条数、总字节和待写队列有界。满额、写入异常、关闭异常必须可见；观察者不能阻塞或改变权威玩法。
- 区分捕获数据、写入成功回执和关闭成功回执。文件可读不证明最后两者；进程收尾失败不能由离线汇总的 0 覆盖。写后报错保留 unknown，不伪造肯定结论。
- 终态与因果链分别核验。缺来源时间不能用排队时间顶替；没有终态事件不能推断仍在思考或合法沉默；回收加迟到丢弃不是两次发言。
- 既要测真实 beta 入口到文件的路径，也要把故障文件送进离线汇总器。只检查进程内状态或只检查文件都不能覆盖收尾一致性。
- 新增错误工厂要进入既有错误码收集与分类检查；不能只登记恰好被字面量扫描命中的一条，也不能更换抛错写法绕过覆盖。配置错误与内部记录失败按实际处置分别归类。
- 权威时间差不是纯模型耗时；本地脚本、正常 JSON 或成功关闭都不能替代真实宿主主动 AI 门禁。具体范围与 R1–R8 见任务中的 B11 取证计划。

## 受控 beta 子进程关停（B13）

### 1. 范围

只处理本机 `src/run-beta.cjs` 的进程生命周期，复用 `startBeta().close()`；不新增 HTTP 关停接口、模型能力或游戏规则。
`test-support/beta-process.cjs` 只控制自己 fork 的进程，不寻找或接管已有 beta，不终止宿主管理进程。

### 2. 签名

```js
startBetaProcess({ env, execArgv, startupTimeoutMs, shutdownTimeoutMs, maxOutputBytes })
// 同步返回 { child, ready, banner, stdout, stderr, stop, disconnect, forceKill }
// await ready 得启动行；stop() 重复调用返回同一个 Promise。
```

控制器默认随机回环端口、关闭适配器及记录，并清空既有 TokenGame 连接环境变量；显式 `env` 才覆盖。
它属于本地测试支持，不是新的桌面宿主启动能力。`execArgv` 仅用于调用者自己的测试进程，不能来自玩家或模型文本。

### 3. 请求、响应与环境

只有 Node fork 继承的 IPC 通道接收以下恰好两个字段：

```json
{"schema":"tokengame.beta-control.v1","command":"shutdown"}
```

不得接受额外字段、路径、令牌或任意命令。关闭路径在异步启动前注册，等待本次启动、停驱动和 HTTP、关闭记录，排空输出后断开 IPC。
没有启用 `TOKENGAME_AI_RECEIPT_FILE` 时不建记录文件，也不输出记录关闭回执。
启用后继续输出 `tokengame.ai-lifecycle-close.v1`；成功条件仍是捕获、写入、文件关闭三项都为真。

### 4. 校验与失败矩阵

| 情况 | 必须发生 | 不得宣称 |
| --- | --- | --- |
| 合法关闭、重复关闭 | 只关闭一次、同一退出结果 | 多次 footer 或多次收尾回执 |
| 非法控制消息 | 服务仍可响应正常请求 | 已关闭 |
| 父通道意外断开 | 捕获结束前改为 `abnormal_close`；已落盘则不回写，但进程仍非零退出 | 整体正常完成 |
| 写入、文件关闭或输出排空失败 | 有界失败、非零退出 | 因文件可读或退出事件而成功 |
| 关闭超时、强制结束 | 只处理自己子进程，报告非正常及实际退出状态 | graceful 或回执完整 |

等待、输出量、异常清理都有上限；正常关闭不能靠输出后立即 `process.exit(0)`。失败兜底强退不能算正常退出。
保留首个错误原因时，后续输出截断/I/O故障仍须独立标记；晚于最后排空检查的输出错误也必须立即把进程退出码置为失败。

### 5. 正常、边界、反例

- 正常：两席经正常 HTTP 发言，脚本 AI 形成一次终态，父进程发关闭消息并收到真实子进程退出；首尾和关闭回执对应同一 `run_ref`。
- 边界：未开记录、启动期间关闭、连续重复请求；不得泄漏服务或重复结束。
- 反例：父通道断开、文件写后报错、输出回调悬挂、关闭消息增加字段。失败事实必须可见，不通过更改扑克时钟或模型配置让它变绿。

### 6. 测试断言

真实 fork 测试必须同时核对 HTTP 端口释放、文件 footer、stderr 收尾行、实际 `exit` 与两条 stdio 的 `end/close`，不假定这些事件的先后顺序。
正常路径有一次真实权威来源和脚本终态的整合检查，不能只有空日志；脚本不是宿主模型。
非法消息、断开、超时和 I/O 故障须实际跑到分支；变异锚点失效记未评估，不能等同杀掉。
本机 IPC 测试不证明 Windows PTY 的 Ctrl+C 传递；没有该载体实测就保留 unknown。

### 7. 错误与正确做法

错误：看到端口消失或离线汇总退出0，就认定真实宿主调用和记录关闭均已成功。
正确：分别记录本次权威终态、文件完整性、进程侧写入和关闭回执、子进程退出；宿主主动 AI Gate 5 另按原任务直接证据裁决。

## 有界自动通知会话（B15）

- 连接管理属于已有协调器，专有 queue 发送器由 beta 显式注入。默认关闭；本人已有席位授权和另一次有界窗口启动是独立条件，不修改模型工具白名单。
- 单槽必须由同一 intent→turn 的实际权威 resolve 回执释放，queue ACK、没有气泡、意图消失、计时结束均不是完成证据。快速 resolve 必须可在 ACK 前被记住，缺失/失败则停止而不猜测 silent。
- 一次通知最多尝试一次，历史和 task→seat 配对有界；停止/重开或 claim 到期不能绕过。一个任务即使已完成回复也不能在同服务内改给另一席，模型上下文不会因监听停止被清空。
- 发送器固定操作者配置的一个游戏任务，真人输入 UUID 不产生任意任务唤醒能力。静态架构检查只豁免专有发送器及 beta 的精确 import，不将整个协调器变成宿主专有模块。
- 每次 await 前后围住停止/世代/时长；取消须传到实际 HTTP fetch（含读响应体阶段），不能仅停止等待并声称底层 I/O 已取消。取消晚于权威效果时，只能扣下返回，不声称回滚。
- queue 的超时/输出异常属于接收不确定，不可按一般 transport 重试。新错误工厂和动态超时代码要进入注册表检查；状态 unknown 与清理未确认均如实保留。
- 本地脚本与 Node 子进程测试不升级真实宿主声明；启停接口尚无 UI 时必须明说。精确配置、端点与重绑限制见 `docs/MANAGED-WAKE-SESSION.md`。

## 两好友远程候选（B30）

- `test-support/remote-friend-browser-acceptance.mjs` 必须从产品 `startBeta` 启动，包含唯一权威到期驱动；两独立浏览器经普通控件建房、加入、Ready 和行动。不能靠特权发牌或测试时钟冒充完整启动链。
- 连接器在 HTTP 返回、读取活动文件、调用本机 sender 各边界验证取消与授权世代；已尝试的通知不得再次 queue，只有同一 ACK 可有界重试。已发送但未确认的清理结果不得写成功。
- 服务器只见不透明目标别名，原生任务 ID 留在本机。身份隔离检查覆盖请求体、错误、DOM、存储和测试摘要；注册、本人授权、通知接收、权威终态是不同事实。
- 入口必须收到肯定的 IPC ready 才报告已接入。真实 Node 子进程测试应覆盖正常注册/撤权退出和未就绪取消，不能只用内存 EventEmitter 代替进程生命周期。
- 修改或迁移变异锚点后检查唯一命中、有效注入和实际失败原因。引用失效局部变量引发 `ReferenceError` 不算对应业务不变量被锁住；变异不能与浏览器/其他回归同时修改同一份源码。
- Web 游戏/配置导航复用同一份席位和连接控件，不得因切换重绑、离桌、续通知授权。双人桌本人底牌和合法动作在桌面首屏可用，窄屏不横向溢出。
- 本地双浏览器、脚本 sender 和真实 Node 进程都不是两台电脑的真实 Codex。发布两好友 MVP 声明仍需 `docs/REMOTE-FRIEND-MVP.md` 的双机、双原生 AI、十手与真人反馈；其他历史宿主探针不自动继承通过。
