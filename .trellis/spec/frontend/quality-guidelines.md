# 质量规范

## 当前质量基线

- Node.js 最低版本为 22，测试命令是 `npm test`。
- 测试使用 `node:test` 与 `node:assert/strict`，并以 `--test-concurrency=1` 串行运行，避免端口、环境变量和子进程互相干扰。
- 当前没有 ESLint、格式化器或 TypeScript 检查脚本；不得把不存在的检查写成已通过。
- 插件相关变更除自动测试外，还要按 `docs/HOST-PROBE-CHECKLIST.md` 在真实 Codex 宿主验证；牌桌 UI 使用 `test-support/four-player-smoke.mjs` 在四个隔离浏览器上下文完成跨身份烟测。

## 必须保持的模式

- 修改权威状态机时，覆盖成功、幂等重放、幂等冲突、配额、关闭和截止时刻边界。
- 修改 Hook 时，同时覆盖普通会话零桥接、公开 Prompt 先登记、Stop 发布、桥不可达失败关闭和 Stop 重入。
- 修改 HTTP/MCP 时，至少覆盖握手、工具清单、状态调用、补交和 UI/机器状态共存。
- 修改扑克领域或牌桌权威层时，至少覆盖合法/非法行动、最小完整加注、短额 all-in、主池/边池、平池奇数筹码、筹码守恒、超时和逐玩家底牌隔离。
- 修改座位旁公开 AI 投影时，四浏览器烟测至少覆盖合法 prompt→generating→matching answer、第二席独立配对、未知/孤立/错席回答、重复请求、旧回答晚到、文本注入负例、全局阶段一致性、完整事件数和桌面/窄屏几何不遮挡。
- 启动真实服务器的测试必须在 `finally` 中停止服务；临时目录必须在 `finally` 中清理。
- 时间相关状态机通过注入 `now` 和 `idFactory` 做确定性测试，不依赖真实等待。
- 任何用户或模型文本进入 DOM 时使用 `textContent`。

真实测试组织：

```js
test("截止时刻及之后拒绝回答，但已公开提示保留在事件流", () => {
  const clock = deterministicStore();
  // 注入时钟，直接跨越 deadline，再验证权威事件。
});
```

## 禁止模式

- 用固定 `sleep` 等待状态机到期，制造慢且不稳定的测试。
- 只测试 HTTP 200，不验证事件数量、顺序、持久状态和无副作用路径。
- 在普通 Codex Prompt/Stop 路径调用桥，即使调用内容只是健康检查。
- 吞掉协议解析错误后继续假装成功。
- 为了让测试通过而放宽幂等、截止时间或隐私不变量。
- 把浏览器截图当作功能测试的唯一证据。
- 只断言事件计数标签而不比较实际渲染列表长度，或只检查座位气泡而遗漏全局阶段状态。

## 审查清单

- 权威性：业务决定是否仍只在 `EventStore`？
- 顺序性：公开提示是否一定先于模型生成，回答是否只发布一次？
- 隐私：普通会话是否仍为零桥请求？公开输入是否可能诱导读取其他任务或文件？
- 故障：桥断开、无效 JSON、窗口到期、Stop 重入是否失败安全？
- 状态：客户端是否只投影服务器事实，派生状态是否可重新计算？
- 清理：服务、SSE、子进程、定时器和临时目录是否可靠释放？
- 证据：自动测试、真实宿主探针和文档结论是否明确区分？
- 多身份：浏览器烟测是否真的使用隔离 context，并经正常玩家接口完成，而不是在一个全知页面切换座位？
