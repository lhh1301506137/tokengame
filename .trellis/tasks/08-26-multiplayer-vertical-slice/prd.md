# TG-L3 多人牌桌垂直切片

## 目标

把现有“单行动窗口 + 公开 AI 事件”探针推进为固定测试桌上的一手完整多人无限注德州扑克：由服务端维护唯一权威状态，客户端只能提交合法行动并观察各自有权看到的投影，最终可通过弃牌或摊牌完成可解释结算。该切片用于验证多人牌局核心，不用于证明生产部署或完整 TokenGame 已完成。

## 已知事实

- `TG-L2-PLAYABLE-TABLE` 已由用户确认：固定规格公开测试桌、不可兑现测试筹码、标准无限注德州扑克、隐藏底牌、公共状态同步、必要边池、行动超时和短暂恢复属于 MVP 章程。
- 受保护规则：其他玩家全部弃牌时，获胜者默认不强制亮牌但可自愿亮牌；进入标准摊牌的仍在局玩家按规则展示。
- `TG-L3-CODEX-BRIDGE-SPIKE` 已通过 11 项自动化、浏览器和真实 Codex 0.145.0 宿主探针；它证明接入链路，不证明完整多人牌桌。
- 当前 `EventStore` 是单进程内存权威源，已有单调事件序号、服务端截止时间、幂等请求和公共状态投影，可作为切片演进起点。
- 当前 UI 是独立原生 Web 页面；首个牌桌切片继续使用独立 Web，不承诺 Codex 桌面内嵌 UI。
- 当前项目无数据库、账号系统、WebSocket 依赖、构建器、TypeScript、Git 仓库或 CI。
- 用户明确要求：TokenGame 是 Codex 内的德州扑克，不重新设计成熟德扑玩法；可由官方规则与成熟线上牌室机制推导的内容不应反复要求用户裁决。
- 用户在体验验收时认可当前牌局机制，但指出全局 AI 流程卡片没有表现“每位玩家和自己的 AI 一起坐在桌边”的核心关系；座位旁 AI 与公开聊天气泡现已完成并通过 AI 验证，当前切片的用户体验验收仍保持开放，直到用户重新体验确认。

## 临时假设

- 首个切片只运行一个进程内的固定测试桌；浏览器或自动化测试驱动器分别以受控身份连接，不引入服务端智能机器人。
- 一手牌从确定性座位、筹码和庄位开始；先证明规则正确性，再扩展大厅、匹配和长期账户。
- 实时观察可继续使用 SSE，下行动作使用 HTTP；只有证据表明双向连接是本切片的必要条件时才引入 WebSocket。
- Codex 公开 AI 通道只需与新牌局事件模型保持可集成，不在本任务重做插件生命周期和远程认证。

## 开放问题

- 当前切片无阻塞开放问题；用户已确认完整 PRD，并授权进入实现与验收。

## 研究引用

- [`research/authority-engine-and-transport.md`](research/authority-engine-and-transport.md) — 推荐独立纯领域状态机与逐玩家安全投影，首切片保留 HTTP POST + SSE；不直接采用高迁移成本框架或未经审计的新扑克规则包。
- [`research/mature-online-poker-rules-baseline.md`](research/mature-online-poker-rules-baseline.md) — 标准牌局行为直接继承成熟无限注德州扑克；线上超时采用“可过牌则过牌，否则弃牌”，具体持续时间配置化。

## 可行方案

### A. 项目内纯领域状态机 + HTTP/SSE（推荐）

- 扑克规则、合法行动和结算进入独立纯模块；表级权威层负责身份、版本、幂等、截止时间和事件序号。
- 对每位玩家分别投影快照与事件，测试使用固定牌序，浏览器继续用 POST 提交动作、SSE 接收更新。
- 与现有架构连续，首切片验证面最小，但需要严谨覆盖短额 all-in、边池和平分。

### B. 迁移到 boardgame.io

- 获得现成多人 master、阶段和玩家视图，但会同时替换当前状态、传输和客户端抽象；仍不能省掉扑克规则与秘密事件过滤。

### C. 采用第三方完整扑克规则包

- 可能更快覆盖边池和 all-in，但当前最贴合的 Node 候选发布历史极短且缺少清晰源码仓库元数据；在源码审计和交叉测试前不应成为权威源。

## 决策（ADR-lite）

### ADR-001：四席、四个独立身份的固定测试桌

- **背景**：首切片需要同时证明多人同步、底牌隔离和至少三名玩家参与的边池结算；单浏览器热切换身份或服务端机器人都会削弱隔离证据。
- **决定**：固定 A、B、C、D 四个席位，每席使用独立身份与独立玩家投影。人工验收可打开四个隔离浏览器上下文；自动化可替未人工操作的身份提交确定性动作，但仍经过与真人相同的权威接口。
- **后果**：本切片必须提供可独立寻址的测试身份入口，并验证四个客户端收到一致公共序号、只收到自己的隐藏信息。无需实现智能机器人、机器人策略或特权全知客户端。
- **状态**：用户于 2026-08-26 选择方案 1，已确认。

### ADR-002：项目内纯领域状态机与现有 HTTP/SSE 边界

- **背景**：现有探针已有 HTTP 动作、SSE 事件、幂等和事件序号；外部框架或新扑克包会同时扩大迁移面与审计面。
- **决定**：按方案 A 推进：牌局规则进入项目内纯领域状态机，表级权威层处理身份、版本、截止时间和投影；首切片继续使用 HTTP POST + SSE。
- **后果**：规则正确性由确定牌序的单元/集成测试承担；未来若真实网络证据要求 WebSocket，可替换传输层而不改领域状态机。
- **状态**：当前技术决策；若实现证据否定关键假设，再回到 PRD 修订。

### ADR-003：成熟规则优先，不重新设计德州扑克

- **背景**：牌局行动、下注轮转、all-in、边池和摊牌已有成熟规则。把这些项目逐一当作产品偏好会增加无效决策，并产生无意变体。
- **决定**：按“TokenGame 受保护特例 > 标准无限注德州扑克 > 成熟线上牌室机制 > 有记录的本地裁决”解析规则。只有来源冲突或 Codex 场景确实不同才新增 ADR。
- **后果**：实现必须维护规则符合性测试表和来源指针。赛事专属规则不会被盲目搬入固定测试桌；time bank 秒数等平台差异做配置或延后，但超时结果固定为可过牌则自动过牌、否则自动弃牌。
- **状态**：用户于 2026-08-26 明确纠正，已采纳。

### ADR-004：座位旁 AI 同伴与最近一组公开对话气泡

- **背景**：当前右侧 `Prompt → Model → Answer` 流程能解释协议，却把公开人机互动表现成全桌共用的后台通道，削弱了“每名玩家带着自己的 Codex AI 入桌”的产品辨识度。
- **决定**：A、B、C、D 每个座位旁都显示自己的 AI 同伴。只有已进入权威公开 AI 事件流的本局 prompt/answer 才形成座位聊天气泡；prompt 先出现，等待回答时显示生成中状态，answer 到达后与同一请求配对。桌边每位玩家只保留最近一组，完整历史继续由右侧公开事件流承载。
- **后果**：前端必须按事件 `actor` 和 `request_id` 派生逐座位会话，不新增第二份业务状态，不把普通 Codex 内容、未知来源或未被服务端接纳的文本显示成桌内对话。长文本需限制占位并保留可访问的完整内容，气泡不得遮挡核心牌面和行动控件。
- **状态**：用户于 2026-08-26 在体验验收中明确提出，已确认；属于既有 L2 语义下的 L3/L4 表现修正。

## 需求

- 固定测试桌包含 A、B、C、D 四席；四席是四个独立身份、会话视图和权限投影，而不是同一特权客户端内的座位切换。
- 自动化测试驱动器可控制未由人工操作的席位，但必须通过正常玩家动作接口，不得读取牌堆或其他席位底牌来决定动作；本切片不要求智能机器人。
- 服务端生成一手唯一牌局，并维护牌堆、庄位、盲注、座位、筹码、当前下注、底池、公共牌、当前行动者和行动截止时间。
- 每位玩家只得到自己的底牌和公共事实；任何公共接口、事件或错误不得泄露其他仍隐藏的底牌或剩余牌堆。
- 服务器按当前下注状态计算可用行动及金额范围，并拒绝越权、过期、重复、非当前玩家或金额非法的动作。
- 支持 preflop、flop、turn、river 的行动轮转，以及 fold、check、call、bet/raise、all-in。
- 按标准无限注规则计算最小下注、最小完整加注和行动是否重新开放；不足完整加注的短额 all-in 不为已行动玩家自动重开加注权。
- 一手牌可因只剩一位未弃牌玩家结束，也可进入摊牌；结算必须守恒筹码并给出可观察的获胜原因。
- 至少覆盖本切片会实际产生的主池/边池结算；不能以“UI 不触发”替代服务端正确性。
- 所有客户端按权威事件序号观察同一公共进度，并可在短暂断开后读取当前投影恢复。
- 玩家在截止前未行动时，若当前无需投入筹码则由服务器自动 check，否则自动 fold；系统不得替超时玩家自动 call、bet、raise 或 all-in。
- 断线本身不暂停权威牌局；客户端可在当前截止前重连并恢复。首切片的倒计时长度由桌配置和注入时钟控制，不实现可累积 time bank。
- UI 明确区分官方牌局事实、玩家私有信息和公开 AI/语言事件。
- A、B、C、D 每个座位旁都有可辨认的 AI 同伴；公开 prompt 显示为该玩家的聊天气泡，匹配 answer 显示为其 AI 的聊天气泡，等待回答时可见生成中状态。
- 座位气泡只消费服务端已接纳的 `AI_PROMPT_PUBLISHED` / `AI_ANSWER_PUBLISHED`，按玩家来源和请求 ID 配对；普通 Codex 消息、未知来源和未公开文本不得进入牌桌气泡。
- 为避免遮挡牌桌，每个座位只保留最近一组公开人机对话，完整事件历史仍保留在右侧公开事件流；四个玩家视图对同一公开气泡保持一致。

## 验收标准

- [x] 四个隔离客户端上下文能分别以 A、B、C、D 身份加入同一固定测试桌；它们观察到相同的公共牌局标识、阶段和单调事件序号。
- [x] 任一客户端与自动化日志都只能获得该身份自己的底牌；不能通过切换前端参数或调用其他玩家投影接口读取别人的隐藏信息。
- [x] 确定性测试可从开局推进到一次弃牌获胜，并证明底牌默认不公开。
- [x] 确定性测试可从开局推进到一次标准摊牌，并验证牌型、赢家、分池和筹码守恒。
- [x] 至少一个由三个独立玩家身份参与的 all-in/主池与边池场景由固定牌序自动化验证，不出现筹码丢失、无资格获池或重复支付。
- [x] 非当前玩家、非法金额、重复动作和截止后动作均被权威服务拒绝且不改变请求预期之外的牌局状态；截止时仅发生合同规定的服务端自动动作。
- [x] 规则符合性测试覆盖最小下注/加注、短额 all-in 不重开、多层边池、平池及奇数筹码、摊牌公开范围/赢家次序和弃牌直接获胜，并绑定规则来源矩阵。
- [x] 注入时钟证明超时只会生成合法的自动 check 或 auto-fold，且不会为玩家投入任何新增筹码；在截止前重连可恢复同一权威状态。
- [x] 不同玩家投影只包含各自允许看到的私有信息；未授权底牌在 API、SSE 和错误中均不可见。
- [x] 客户端按事件序号恢复后与服务器当前状态一致，不依赖本地重放猜测牌局。
- [x] 独立 Web 牌桌能观察一手完整牌局并提交测试动作，浏览器控制台无错误。
- [x] 原有 Codex 桥接 11 项测试继续通过。
- [x] 四个座位旁均显示各自 AI 同伴；至少一个真实公开 prompt 在所有四个隔离浏览器中立即显示为来源玩家气泡，并在 answer 到达前显示生成中状态。
- [x] 匹配 answer 到达后在所有四个视图中显示为同一座位 AI 气泡；`render_game_to_text()` 同步给出逐座位最近对话，未知来源不会生成座位气泡。
- [x] 长文本、四席布局和窄视口下气泡不遮挡公共牌、玩家关键状态或行动控件；浏览器控制台仍无错误，完整牌局烟测继续通过。

## 明确不在范围内

- 真实价值筹码、充值提现、长期账户经济、排行榜和锦标赛。
- 私人房间、好友邀请、观战、大厅匹配、多桌和多种扑克规则配置。
- 生产 OAuth/TLS、数据库持久化、水平扩展、跨节点一致性和公网发布。
- 完整聊天审核、举报、禁言、年龄或地区合规体系。
- 智能扑克机器人、服务端代打策略、全自动 AI 座位，以及拥有全桌隐藏信息的调试玩家界面。
- 自创德州扑克变体、锦标赛盲注升级、ante、抽水、买入/补码，以及累计 time bank 或按底池变化的断线保护。
- Codex 桌面原生嵌入牌桌、不可伪造的模型来源证明，以及插件跨平台生命周期收口。
- 在本切片内重做公开 AI 时序合同；只保留与权威牌局上下文对接的边界。
