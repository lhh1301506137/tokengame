## B9 时延拆分对本探针的约束

只复算已有过滤日志，详见
[B9 时延研究](./b10-b9-latency-breakdown-20260830.md)。成功样本中，玩家来源事件到权威公开为
33.460 秒，公开到最终可见回执还有 11.556 秒；44.917 秒是整轮记录，不能全部归为“想好台词”的时间。
take/start 已在同一执行单元顺序调用，共享 95ms 包络；其独立耗时与纯模型推理时间均 unknown。

该次公开发生在行动截止后 3.822 秒，`late=false` 只反映未跨街，不能证明赶上扑克计时。
因此不改行动时钟、不声称减少一次模型往返、不报告推测的提速率。本轮预领取只控制通知资格；
未来原生任务仍须及时 start，沿用现有 30 秒 claim 租约。缩短最终回执可能减少任务收尾占用，
但不会使已经公开的同一次发言提前。

## 最小实现合同（仅 test-support）

- 一个探针实例最多一个队列发送尝试，无自动重试，不做通用常驻调度器。
- 由已授权的本席 MCP 连接读取 `view.timeline`：先建立现有事件基线，再等待指定公开席位的新
  `PLAYER_PUBLIC_SPEECH`。旧事件、重放、其他席位以及 `AI_PUBLIC_SPEECH` 不触发。
- 这是对本地权威状态的有限轮询，不是定时调用模型。没有新合格事件时调用模型次数必须为零。
- 出现新事件后，通过同一模型命令面调用一次 `ai.take_intents`，必须只有本席并只有一个合格 intent。
  校验来源对应刚观察到的权威事件。空待办、AI OFF/忙碌/配额耗尽或来源已被新上下文替代时停止，
  不自行重判规则，不继续领任务。后续全面事件合并不属于这个单次探针。
- 仅把经格式校验的 `intent_id` 和探针编号放入固定 LOCAL_CONTROL 通知。通知不包含聊天正文、
  底牌、令牌、连接文件内容、系统路径或对手可控指令，不以玩家身份公开。
- 原生游戏任务用已配置 `tokengame_table` 执行一次 `ai.start`，成功后只用返回的本席
  `model_context` 生成一次 `silent | public_speech` 并调用 `ai.resolve`。探针不调用 `ai.start`
  或 `ai.resolve`，不读取本席私有牌面、不代写 AI 台词，也不执行任何扑克动作。
- Claim 到 start 沿用现有权威租约与绑定世代围栏。失效就失败，不延长租约/牌局时钟。
  本地预领取用于保证“有合格待办才通知”。B9 成功轮的 take/start 已在同一个执行单元顺序调用，
  不能声称本轮因此省掉了它的一次模型往返；是否改善时延必须另测。
- 实际队列命令必须有显式 opt-in，默认模式不创建 MCP 子进程、不连牌桌、不领取待办、不启动 Codex。
  可执行文件和工作目录为显式绝对路径，thread 为 UUID，shell=false，Windows 窗口隐藏；固定参数数组。
- 等待总窗口、单次 I/O 和子进程输出均有上限。取消/截止后不得再发送；发起发送前检查边界，
  子进程错误/超时/取消后结果按 unknown 处理而不是重试。
- 退出必须关闭本探针自己的 MCP/队列子进程和计时器；不得清理旧 beta、其他 Codex 任务或用户文件。
  已被宿主接收的消息无法由停止本探针保证撤回，这个风险必须单列，不能写“已取消模型回合”。
- 结果仅记录净化后的观察、尝试次数、原因和时间。退出 0/queue 接收不等于 Gate 5 PASS。
  自动化层的 `gate5_status` 始终为 `not_run`，不写入 `verified_on_any_host`。

## 本地验证义务

1. 默认关闭零副作用；无事件/历史事件/AI 自激/错触发席位零领取零队列。
2. 多个新事件只取最新合格事件，并只发送一次；重放不重复。
3. 空待办、多待办、跨席、来源不符、协议坏形状、权限撤销/网络失败必须失败关闭。
4. 取消与截止覆盖 await 前后，包括领取后尚未发送以及发送结果不明；不回补、不重试。
5. 队列参数不能覆盖模型/强度、不能执行 shell；消息与日志不包含对手注入文本或私有字段。
6. 一个真实本地协调器 + 两个独立席位 + MCP stdio 的测试，确认待办由正常公开聊天产生，
   被指定席领取；模拟队列接收端可走既有 ai.start/resolve，证明入口连通，明确标注脚本接收端。
7. 清理失败不能冒充干净完成。既有 B8/B9 源码与原始证据不改写。

## 当前接口与测量边界

默认关闭入口为 `node test-support/codex-queue-wake-probe.cjs`。
有授权的实验才可传 `--live`，并显式指定 `--node-exe`、`--codex-exe`、`--cwd`、
`--connection-file`、`--thread`、`--trigger-seat`、`--probe-id`；没有隐式寻找任务或扫描连接目录。
本文件不提供可自动执行的真实窗口授权，`--live` 也不能代替用户对本窗口的同意。

CLI 有效启动后，先在认证后的公开基线读取成功时输出一条
`tokengame.codex-queue-wake-probe.ready.v1` JSONL，仅含 `probe_id` 与 `baseline_sequence`。
脚本 API 可使用同步 `dependencies.onReady` 接收同一信号；调用一次、无正文，不等待模型。
只有观察到此信号后才发送测试聊天。最终结果是另一种 schema，调用者不能把第一行 ready 当成成功结束。

`elapsed_ms` 使用探针单调时钟计算，明确包含清理；它不是玩家事件到模型发言的时延。
本批没有为事件、领取、队列及原生 turn 建立统一分段时间戳，各独立 span 保持 unknown。
下一次实机验证应在外围证据采集器中补齐这些实际观察，不由返回的整段耗时推算。
