# B16：本人有界自动通知控件

## 目标与授权

用户“继续”恢复同一已确认路线。本批在现有牌桌接入 B15 启停接口，不改扑克、公开输入、AI 权限或宿主模型合同。真实模型调用、原生 queue、原生任务输入的本批预算均为 0；只用本地脚本接收端和合成牌桌验证。B14 被拒绝的清理不重试、不绕过。保持既有脏工作树，不 stage/commit/archive/push/deploy。

## 实现边界

1. 在“连接我的会话 AI”面板内新增独立的“自动通知（本地实验）”表单：游戏任务 UUID、通知次数、持续时长、每次新窗口的显式确认，以及开启/停止。不开新页面，不重画牌桌，不嵌套 form。
2. 服务默认关闭。只有当前本人的有效绑定、已确认公开范围、AI ON、发送器已启用时才允许开始。任务仍由发送器固定，页面不能给任意任务排队。绑定/host_seen/发送器 enabled 均不等于原生能力已验证。
3. 复用 `/api/view` 的既有轮询，不加第二个协调器或独立高频循环。新增仅本人可见的 `model_wake: { enabled, limits: { max_notifications, max_duration_ms }, window }`。未绑定时 window 为 null；limits 来自 manager 实际配置，不在页面复制硬上限。配置投影不得暴露目标任务、环境变量、私有路径、模型令牌或其他席位状态。
4. window 沿用 B15 原有状态合同。显示等待/发送/等待权威回执/停止、尝试/接收/resolve 计数、原因、时长及清理不确定性。resolve 包含公开或 silent，不能标为“公开回复数”。停止只停止后续通知，不撤回已经接收的原生消息；AI OFF/解绑才继续使用原有禁止迟到发布的权限围栏。
5. 一次逻辑 start 使用固定 UUID 与不可变参数，阻止重复点击。网络结果不确定时保留原请求，显式重试也必须使用同一组参数；不能自动新建窗口。成功后清空同意，新窗口重新确认。异步结果按 session/binding 世代隔离，解绑、离桌和换绑后不得显示旧窗口成功；旧 poll 不得覆盖新的启停结果。
6. 默认禁用、OFF、请求失败和未知状态不能阻断打牌、公开聊天或解绑。缺失/非法能力投影失败关闭，错误可读。使用安全 DOM 文本、原生标签和键盘控件，支持 1365px 桌面及 390/320px 窄屏。文本状态钩子只反映本人可见信息。

## 验收链

进入自己的牌桌 → 连接本席通道 → 明确开启有限窗口 → 看见通知/等待回执 → 停止或撤权后不再发送。

- Node：真实 view 投影的本人隔离、默认关闭、降低后的实际上限；UI 状态机/重复提交/失败重试/旧响应/换绑清空及未知状态围栏。
- 主线程 Browser 首先检查实际页面、无空白和遮罩、控制台与截图，再操作正常启停、等待及撤权；使用合成接收端，不调用 Codex。
- 同链补充可复跑的浏览器验收与游戏客户端检查；窄屏和控制/聊天互不阻塞。变异检查应实际击中新的关键围栏，未运行不得计通过。
- 独立 checker 检查本批增量，主线程再整合。QA 临时截图、原始日志放仓库外的本批证据目录；现有 B15 证据不覆盖、不改写。
