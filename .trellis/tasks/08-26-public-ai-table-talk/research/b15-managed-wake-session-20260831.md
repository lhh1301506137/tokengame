# B15：单协调器内的有界自动通知会话

## 本批结果目标与边界

沿 B14 已验证的一次 `queue --thread` 路径，把逐次手动运行探针变成可显式启停的本地连接。仍是原任务、原模型；不创建第二个 AI，不改扑克规则，不改公开输入语义。本批只用脚本接收端验证，真实 Codex 连续运行、Claude、四人试玩及实时性仍未验证。B14 Gate 9 的策略阻塞不重试、不绕过。

专业判断：连接管理应放在已有 `TableWebHost` 内，因为它已经拥有唯一的席位绑定、撤销围栏和模型命令面。另建轮询私有文件的常驻 MCP/第二协调器，会重复持有状态并使撤销与关停更难。Codex 特有的进程发送器由 beta 显式注入，协调器自身保持宿主中立。

## 实现合同

1. 默认没有 `wakeQueue` 发送器，启动 beta 不会调用 Codex。只有明确配置发送器、已有本人模型绑定、本人对一次有限窗口作显式启动，才开始轮询权威待办。不开新宿主工具、不改 `MODEL_COMMANDS`。
2. 新的本机真人控制路由为 `POST /api/model/wake/start|status|stop`，认证仍用当前浏览器会话令牌，不把模型令牌、席位凭据或私有牌面交回控制结果。start 要求 `acknowledged: true`、UUID `request_id`、UUID `thread_id`；通知上限默认/最大 4 次，窗口默认/最大 600000ms。参数只能取更小正整数。重复请求幂等，参数冲突或另一活跃窗口拒绝，停止的旧请求不得复活。
3. 每个绑定最多一个自动通知会话、一个待确认通知；同一协调器生命周期内，native thread 只能配对一个 seat handle，即使上一轮已 resolve 也不能改给另一席，因为模型上下文可能仍有前席未公开底牌。停止窗口不等于清空模型上下文。领取仍走该绑定的 `ai.take_intents`，权威负责事件合并、5 秒启动间隔、配额与租约。没有待办只轮询数据，不启动模型。
4. `ModelCommandSurface` 增加仅供协调器使用的有界回执观察：关联已领取的 intent → 已启动 turn → 实际 `ai.resolve` 成功。只保留编号/阶段，不能存正文、model_context、底牌或秘密。换绑/撤销清空，跨席/跨世代不可读。拒绝、空白或丢失回执不能当作 silent。权威超时/网络不确定但没有实际 resolve 回执时，自动通知窗口停止并报告 unknown，不猜下一轮可运行。
5. queue 返回 0 只表示接收，不能释放待确认槽。只有同 intent 对应的权威 resolve 成功才允许下一次领取/通知；native task 可能还在收尾，不能把该事实称为宿主 idle。旧窗口仍有未确认通知时，新窗口即使换任务编号也不得跳过单槽；必须等精确 resolve，或保守拒绝。已尝试的 intent 在当前绑定内不得自动重投，包含停止后重开和 claim 到期重领；去重历史有界且满额失败关闭。
6. 每次 await 前后检查取消、窗口与绑定世代；claim/回执检查等 I/O、通知发送、等待终态分别有上限。AI OFF、离桌、撤权、服务关闭停止后续发送。停止监听不保证撤回已接收的任务，也不冒充原生回合取消；真正禁止后续公开仍由原有 OFF/撤权围栏执行。
7. 发送端接口：`wakeQueue({ threadId, intentId, notificationId, signal })` 返回 `{ queued, attempted, cleanup_ok, reason }`。固定 queue 参数，禁止 shell/模型或强度覆盖，通知只含固定控制文本和合法编号。发送异常、未知接收、超时或清理不完整停止窗口，不自动重试。只管理本次创建的进程，不读取或删除连接文件，不操作宿主管理 MCP。
8. 控制状态区分 idle/waiting/dispatching/awaiting_result/stopped，保留原因、尝试/接收/resolve 计数及清理结果。最多保存受限的当前/历史请求与去重记录；时间和计数不是新的游戏权威。
9. 真实发送器的目标必须由本机配置 `TOKENGAME_CODEX_THREAD` 固定为一个明确的游戏任务 UUID。真人 start 的目标必须匹配；控制接口不能给这台机器的任意普通任务排队。发送器提供只读纯校验 `allowsThread(id)`，协调器在领取前检查，发送器在实际发送前再检查。UUID 目标按大小写等价处理，不能绕过同任务互斥。本批只为一个真实游戏任务准备连接，不宣称四个原生 AI 已接通。
10. 时钟必须有限且不回退；异常立即取消窗口，不产生无限等待或将 NaN 计时写成有效状态。同席可以显式重开窗口，但撤权时已经通知且未确认结果的旧回合不能被猜成结束；该情形的自动重绑恢复不在本批完成声明内。

## 验收矩阵

- 默认零发送、未绑定/未确认/坏 UUID/错误预算拒绝；重复启动幂等、跨席同任务冲突。
- 两次真实本地权威意图：脚本经同席模型面 start/resolve，先公开后 silent；一次 queue 成功但 resolve 尚未返回时，新公开事件只在权威合并，不能发送第二条。
- 返回太快（在 queue ACK 前 resolve）、慢/悬挂/失败、回执缺失、重复 intent、停止后重开、撤权/换代的 await 竞态、AI OFF、达到次数/时长上限。
- 控制结果/通知中没有玩家正文、底牌、模型令牌与席位凭据；模型工具清单与真人动作权限不变。
- 真正子进程发送器使用本地脚本或模拟 spawn，不调用真实 Codex；正常/超时/取消/输出超限及自身进程关停结果均可观察。B10 的八条变异仍可达，新关键围栏补变异。
- 独立检查与主线程整合；没有改 UI 时不将旧截图或旧浏览器测试冒充本批检查。
