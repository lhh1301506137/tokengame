# TokenGame

TokenGame 在探索一种不一样的 AI 游戏形态：**牌局仍是正常的无限注德州扑克，但每位玩家都带着自己的
会话 AI 上桌。玩家与 AI 的赛时讨论会以座位旁聊天气泡公开，其他人既能读牌，也能判断这段对话是在分析、
施压还是联手诈唬。**

> **当前状态：实验性 Alpha。** 核心牌局与单机多人浏览器原型可以运行，Codex 单席真实发言已有
> 有界实测。本轮增加临时 HTTPS 私人房入口、逐玩家本机 Connector 与外部 Web 工作区，
> **两台设备、两席真实 AI 的十手好友验收仍未完成**，不能把本地脚本通过当成实时联机已通过。
> Claude 接入与 Codex 内嵌 UI 不在本轮范围。测试筹码不对应真钱、代币或付费模型额度。

## 这不是“让 AI 替人打牌”

两个操作面属于同一局、同一席位、同一份权威状态：

- **Web 牌桌**是真人的筹码操作面。下注、Ready、确认公开范围、亮牌都在这里，由服务端维护
  唯一权威状态并逐玩家投影隐藏信息。
- **宿主对话**是 AI 与入口控制面。当前实现连接玩家自己的 Codex 任务；Claude 是下一宿主方向。
  该席 AI 只读权威裁剪后的本席上下文并选择公开发言或沉默，**不能替真人下注**。

模型和推理强度跟随玩家自己的宿主会话，不要求项目另配一套模型 API。隐藏底牌、公开牌局、AI 权限与
真人操作由单一权威协调器隔离；“通知已接收”“模型已启动”“AI 已公开发言”是三种不同事实。

## 本地运行

要求 Node.js 22 或更高版本；项目没有第三方运行时依赖。默认只监听回环地址。

```powershell
npm test          # 全量单元测试
npm run gate      # 测试 + 全部变异规格（跨平台，PowerShell 与 Git Bash 同一条命令）
npm run codex:play -- "<当前Codex项目根绝对路径>" # 首选：固定当前任务并安全启动本地原型
npm run codex:configure -- "<Codex项目根绝对路径>" # 高级兼容：只配置项目，不启动
npm run beta      # 高级兼容：手工起协调器；默认没有Codex通知发送器
npm run beta:remote -- "<真人提供的HTTPS根地址>" # 房主：已有隧道下启用远程私人房
npm run codex:connect -- "<当前Codex项目根绝对路径>" # 各玩家：连接已有远程房间，不另起牌桌
npm run connection:activate -- "<下载文件绝对路径>" # 入桌/换发，不重启MCP
npm run connection:clear                           # 撤销后清项目活动槽位
npm run web       # 只起浏览器牌桌（模型命令口关着）
```

**单机测试首选 `codex:play`；异地好友按[远程指南](./docs/REMOTE-FRIEND-MVP.md)使用 `beta:remote` + `codex:connect`。**
不要让两位玩家各运行 `codex:play`，否则会各建一套本地服务。首次运行若更新了项目受管配置，它只会提示重启而不会
启动牌桌；重启目标 Codex 任务后必须重跑同一命令。配置相同也不等于当前宿主已经加载工具，仍以重启后
实际工具发现和调用为准。入口只使用当前任务的`CODEX_THREAD_ID`，不会用session ID代替，也不会把任务
UUID交给页面填写或显示。

从旧版升级后，即使配置未变，也需手动重启 Codex 一次以载入新版 MCP 代码。此后仅入桌、换发或清除
连接文件仍不需要重启；不要把连接文件的热切换误认为代码会自动热更新。

成功启动beta后，让这次Codex启动回复结束并保持该游戏任务空闲，再到Web牌桌开启有限通知窗口。一个任务
不会并发执行两个模型回合；它仍在回复或执行其他工作时，通知可能已接收却要等待当前回合结束，窗口可能
先到限。页面的“已接收”不等于模型已开始或权威已结清。

`npm run beta`保留为高级手工兼容入口。它开启真人逐席授权的模型命令口，但默认没有Codex通知发送器；
需要managed通知时必须显式配置四个变量，见[有界通知说明](./docs/MANAGED-WAKE-SESSION.md#两次显式开启)，
且不会从PATH猜可执行文件。`npm run web`不启用模型命令口，所以那条路是关着的
（`/api/health` 会显示 `model_command_route: disabled`）——牌桌照常能玩，只是没有任何一席的
宿主 AI 能发言。

`npm run beta` 只打印牌桌地址和操作说明，**不生成共享整桌令牌**。每位玩家在自己的页面展开
AI 连接区、确认权限后，下载自己的连接文件；可随时撤销，重新下载会换发权限并使旧文件失效。
令牌不进入页面文本、URL、浏览器 storage 或终端。下载文件是秘密，不要粘贴到对话或提交 Git。
撤销阻止后续调用，不回滚已送入权威处理的请求或历史发言。已启动但未回填的评估按现有
120 秒租约回收；同一真人会话最多保留 128 个换发请求记录，满额明确拒绝，不偷偷复活旧文件。

默认 `beta` 仍只供**同一台机器的独立浏览器上下文**测试：创建房间并确认公开范围后取得邀请码，其余上下文
用邀请码加入。协调器始终只监听回环；真人在进程外自行准备 HTTPS 反向隧道或代理后，可用：

```powershell
npm run beta:remote -- "https://table.example.test"
```

该地址只用于浏览器入口和下载的本席连接文件，不改变内部回环监听，也不信任请求的 `Host` 或
`Forwarded` 头。`beta:remote` 另外启用本席通知长轮询/ACK，每位玩家用自己的 Connector 唤醒自己电脑的
Codex 游戏任务；默认不开模型窗口，仍需本人在 Web 确认。项目不捆绑隧道供应商或 TLS 服务，
不上传原生任务 ID，不改变会话模型。**这些代码与本地测试不代表两好友真实联通或实时性已通过。**

产品形态是内核独立成进程，协调器只是它的客户端：

```powershell
npm run core   # 权威内核，打印自己的地址（默认随机端口）
# 把它打出来的那个地址贴进下一条命令：
$env:TOKENGAME_COMMAND_ORIGIN='http://127.0.0.1:<核心打印的端口>'; npm run beta
```

两种形态行为一致，同一批断言对两种传输各跑一遍。

三个进程角色，各自持有什么是这套东西最要紧的一句话：

| 进程 | 持有 | 不持有 |
| --- | --- | --- |
| 权威内核 | 全部牌局状态、底牌 | —— |
| 协调器 | 席位凭据、会话令牌、模型命令口 | 牌局状态（它是内核的客户端） |
| 宿主插件（MCP） | 从本席私有文件读取受限模型令牌 | 核心席位凭据、句柄、真人会话令牌 |

`codex:play`先只读校验唯一绝对项目根、当前task ID与可信Codex可执行文件，全部通过后才原子更新项目
配置。它只在真人指定项目的`.codex/config.toml`管理TokenGame受管块，不改用户级配置；当前仓库若只是
Codex项目的子目录，应传真实上层项目根。受管`cwd`写入经过canonical校验的本机仓库绝对目录：它是
Codex启动stdio服务器所需的机器本地定位信息，不是席位凭据、令牌或模型配置；稳定CLI/UI输出仍不回显
该路径。仓库跟踪的`.codex/config.toml`只是一份可移植模板，其中的`cwd = "."`不是上层Codex项目的
运行时配置，也不能作为宿主已加载工具的证据。真人生成在上层Codex项目中的`.codex/config.toml`会包含
本机目录布局，不要分享或提交Git；仓库随源码跟踪的可移植模板不在此列。
显式`TOKENGAME_CODEX_EXECUTABLE`无效时不会回退PATH；Windows无显式值时只接受PATH里第一个实际存在且
位于canonical `%LOCALAPPDATA%/OpenAI/Codex/bin/<hex>/codex.exe`的可信文件，非Windows必须显式给出。
之后下载连接文件并运行 `connection:activate`，MCP 每次请求都读取项目
Git 忽略的稳定槽位，换发不再改服务器定义或重启进程。源下载文件仍由真人自行删除；页面撤销服务端
权限后再运行 `connection:clear` 清本地槽位。

## 代码地图

- `src/game/`：德州扑克领域状态机、牌型比较与底池结算。
- `src/authority/`：宿主中立权威内核。房间与席位、逐玩家投影、服务端时钟、事件序号、
  幂等、发言预算与租约回收。命令面在 `command-surface.cjs`，宿主可发什么在 `host-surface.cjs`。
- `src/contract/adapter-contract.cjs`：两个宿主适配器共享的合同。一套协议、两个权限剖面
  （`host_command` 真人面、`seat_model` 模型面），能力按「角色 + 具体宿主剖面」协商。
- `src/host/`：宿主侧。席位凭据托管（`seat-custody.cjs`）、模型命令面、两份参考适配器、
  浏览器牌桌协调器。
- `web/table/`：当前牌桌 UI。
- `plugins/tokengame/`：仓库内 Skill、Hooks 与 stdio MCP 服务。
- `test/` 与 `test-support/`：自动化测试、四上下文浏览器验收驱动器、变异规格与门禁。
- `artifacts/`：本地验收产物，已在 `.gitignore` 中排除。

## 明确不包含

- 公开大厅、自动匹配、公平场、信用体系、市场；
- 账户、生产 OAuth、反作弊、持久化数据库或真钱/代币；
- 对宿主身份的密码学证明；
- 宿主桌面内嵌牌桌（当前使用独立本地 Web 页）；
- 对隐藏推理过程的获取或公开——只处理用户提交文本与最终助手消息。

## 历史实现：A/B/C/D 显式公开桥

早期版本是另一条路径：固定 A/B/C/D 四个身份的一桌牌，加一条 Codex 公开 AI 桥——以
`$tokengame public <message>` 这类前缀标记提示，由 Hook 在模型生成前登记到权威。入口是
`npm run table`（探针栈，`web/app.js` 与 `src/bridge/`）。

**那条路径已经不是产品路径。** `npm run table` 与 `npm run authority` 原样保留为已替代的
历史证据，`docs/HOST-PROBE-CHECKLIST.md` 记录它当时的实机范围。区别不只是入口名字：那时
席位是四个写死的身份，发言靠前缀触发，行动面与 AI 面分属两个互不相认的栈。现在席位由邀请码
建房产生，发言由权威派发的意图驱动，两面属于同一局同一席位。

[历史固定四人探针说明](./docs/MULTIPLAYER-VERTICAL-SLICE.md)与
[历史验收证据](./docs/ACCEPTANCE-EVIDENCE.md)只证明各自记录的版本和范围。
