# 安全与隐私边界

## 当前能保证什么

- 服务只绑定 `127.0.0.1`，不会主动监听局域网或公网接口。
- 只有三个严格前缀会把用户文本视为公开 TokenGame 内容；普通 prompt 和没有 pending 标记的普通 Stop 不调用桥。
- 权威公开事件不包含 Codex 项目文件、历史对话或隐藏推理；公开事件只携带显式 prompt、最终回答、请求/窗口 ID 与服务端时间。
- 公开回答待提交期间，`PreToolUse` 对 Codex 可拦截的非 TokenGame 本地工具返回拒绝。
- 对手文字被注入的上下文明确标为不可信内容；公开建议不自动转化为牌局动作。

## 当前不能保证什么

- 固定开发 token 不是生产认证。本机上的其他进程仍可能访问回环端口；浏览器探针 API 也有意开放给本机 UI。
- Codex Hook 对 hosted tools 的覆盖不完整，`PreToolUse` 只是降低泄漏概率的护栏，不是数据隔离边界。
- 当前 `PLUGIN_DATA/terminal` 会保留已公开文本与提交结果，尚无保留期或用户清除界面。
- 伪权威服务使用内存状态，进程重启即丢失；它不能提供审计级持久性、签名或跨节点一致性。
- 没有证明回答来自某个特定 Codex 二进制、账号或不可篡改模型；UI 不得展示“Codex verified”。

## 产品化前的必需替换

1. 远程权威服务采用正式身份认证、短期会话凭据、TLS、速率限制和服务端审计。
2. 公开内容与私有项目上下文必须运行在专用、最小工作目录和专用 Codex 任务；不能复用包含秘密的开发任务。
3. 将固定 token、开放 CORS 和本地调试窗口控制 API 移出生产构建。
4. 明确定义公开日志的保留、删除、导出、举报与未成年人保护策略。
5. 对 prompt injection、恶意超长文本、Unicode 混淆、重放、断线重连和客户端时钟欺骗做独立安全测试。
