# 两好友远程内测

本轮目标是两台电脑、两名好友、各自一个 Codex 游戏任务，在同一私人房连续玩至少十手。
先验证普通德州与真实 AI 公开交流，不购买服务器，不建设公开大厅。

当前是实现候选，**尚未完成两好友真实联通验收**。本地脚本结果、原生模型结果与真人签字分别记录，
最新本地收口证据见 [B33 记录](../REVIEW-LOG.md#b33-poker-maturity-and-refill)。

## 连接方式

```text
房主 Web ───────┐
好友 Web ───────┼─ HTTPS 临时入口 ─ 回环协调器 ─ 唯一牌局权威
房主 Connector ┤                     │
好友 Connector ┘             本席通知 / 本席模型命令
      │
      └─ 只唤醒自己电脑的 Codex 游戏任务
```

玩家电脑不开放入站端口。牌桌仍由房主电脑维持，关机或关闭服务就会中断；首轮不提供进程重启后的房间恢复。
这是可信好友内测，**不是防作弊的公共牌室**：房主掌管权威进程，HTTPS 隧道供应商也处在传输信任边界内。
测试筹码不对应钱、付费额度或真实 tokens。

## 房主准备一次入口

1. 两端先冻结同一提交并各自完成本地预检。推荐使用 CI 已覆盖的 Node.js 22 或 24；所有 `npm run`
   命令都在有 `package.json` 的 `tokengame` 仓库目录执行，不在 `C:\Windows\System32` 执行：

   ```powershell
   Set-Location "C:\path\to\tokengame"  # 换成各自实际仓库路径
   git switch main
   git pull --ff-only
   git status --short
   git rev-parse HEAD
   node --version
   npm test
   ```

   两人把 `git rev-parse HEAD` 的完整输出互相核对，必须完全相同；`git status --short` 应无输出，
   `npm test` 必须退出 0。项目无需额外的 npm 运行时依赖，但 Codex 和所选隧道客户端仍须就绪。
   本批开发验证在 Windows；其他系统的真实宿主入口尚未验证。
2. 房主自行选择并显式启动 HTTPS 反向隧道，转发到 `http://127.0.0.1:7802`。
   例如已安装 Cloudflare 的客户端时，在单独终端运行：

   ```powershell
   cloudflared tunnel --url http://127.0.0.1:7802
   ```

3. 把客户端实际打印的 HTTPS **根地址**交给另一个终端中的 TokenGame：

   ```powershell
   Set-Location "C:\path\to\tokengame"  # 换成房主实际仓库路径
   npm run beta:remote -- "https://实际生成的地址.trycloudflare.com"
   ```

4. 房主与好友用浏览器打开同一 HTTPS 地址。房主建房并确认公开桌规，好友用邀请码加入。
   先确认两端是不同玩家，完成下方双方 AI 连接后再 Ready，避免配置期间自动消耗行动时间。
   浏览器重连使用原浏览器上下文，不要清除会话存储。

`beta:remote` 不安装、不启动隧道，不修改防火墙；它显式启用远程 Connector 接口，协调器仍只监听回环。
普通 `beta` 默认不开通知发送器。仅设置 `TOKENGAME_PUBLIC_ORIGIN` 也不会自动启用远程通知。
根地址不能带账号、密码、路径、查询或片段；不根据请求头猜公网地址，不携带令牌自动跟随重定向。

Cloudflare 只是可选示例，不是产品依赖。其 Quick Tunnel 是无 SLA 的测试功能且不支持 SSE；
当前牌桌短轮询与 Connector 长轮询不依赖 SSE。参见
[官方说明](https://developers.cloudflare.com/cloudflare-one/networks/connectors/cloudflare-tunnel/do-more-with-tunnels/trycloudflare/)。

## 每位玩家连接自己的 AI

双方都要独立完成下列操作；**远程好友不要运行 `codex:play`**，那会在自己电脑另起本地牌桌，
不是连接房主已有牌局。两位玩家也不能共用一个活动连接文件或 Codex 游戏任务。

1. 在自己的 Codex 项目中准备一个专用游戏任务，开发、审查等长任务放在别处。第一次先配置项目：

   ```powershell
   npm run codex:configure -- "<自己 Codex 项目根的绝对路径>"
   ```

   路径是 Codex 实际打开的项目根，可能是仓库的上层。若配置改变，按提示手动重启 Codex，确认
   `tokengame_table` 已加载；文件存在不等于当前宿主已加载。配置器只管理该项目的 TokenGame 块，
   不改变模型、推理强度、账号、provider 或用户级配置。

   从旧版升级到本版时，即使配置没有变化，也需手动重启 Codex 一次，让已有 MCP 进程载入新版代码。
   此后仅入桌、换发或清除连接文件不需要重启；代码升级与连接文件切换是两回事。

2. 在 Web 的配置中心，明确授权**自己的席位**并下载本席连接文件，再在自己的仓库目录激活：

   ```powershell
   npm run connection:activate -- "<自己下载文件的绝对路径>"
   ```

   文件含本席读牌/AI 发言权限；不要发送给朋友、贴进聊天、提交 Git 或放在共享文件夹。
   不需要复制令牌，不需要第二套模型 API。激活不自动开窗；源下载文件由真人自行安全删除。

3. 在该专用 Codex 游戏任务中让 Codex 执行：

   ```powershell
   npm run codex:connect -- "<自己 Codex 项目根的绝对路径>"
   ```

   该命令必须在目标 Codex 任务环境内运行，不能用普通终端冒充任务身份。成功注册前不会报告
   “已连接”；若要求重启，重启后重跑。它使用当前任务的原生 ID，仅在本机传给可信 Codex 发送器；
   服务器仅见稳定的不透明目标别名，不接收原生任务 ID 或 Codex 登录凭据。

4. 让这次 Codex 回复结束，保持游戏任务空闲。回到 Web，等待“本机连接器已接入”类状态，再由本人
   勾选有限通知窗口的确认并开启。两位玩家分别确认，彼此不能代开。窗口默认最多 **4 次 / 10 分钟**，
   达到实际显示的次数/时限就停止；需要继续时本人重新开窗。

Connector 最长运行一小时只是传输寿命，**不是一小时无限模型调用授权**。它不会自动 Ready、下注、
开启通知窗或替玩家聊天。当前任务繁忙时，通知可能已接收但模型尚未开始；先结束游戏任务内其他工作。
同一项目的本席活动槽位只能服务一个玩家，不能把它宣传成密码学任务隔离。

## 故障和停止

| 情况 | 应有行为与操作 |
| --- | --- |
| 短暂断网 | 长轮询有界重连；同一通知的 ACK 可重试，已经尝试过的通知不再 queue。真人时钟继续。 |
| 更换或撤销连接文件 | 当前连接器停止，不偷偷切到新席；激活新文件后在正确游戏任务重跑连接。 |
| 通知已发送但 ACK 不明 | 不自动补发；可能已经唤醒，不能把断线当作“从未执行”。检查原任务与页面状态后再处理。 |
| AI 慢或不可用 | 可以关闭座位 AI，继续纯手动打牌；不会换一个外部模型，也不会延长德州行动时间。 |
| 暂停新通知 | 在 Web 停止自己的通知窗口；这不能撤回已经进入 Codex 的回合。 |
| 本次退出 | Web 停窗、关闭 AI 并撤销本席连接，再运行 `npm run connection:clear` 清本机活动槽。房主最后停止牌桌与自己的隧道。 |

浏览器短断保留与扑克计时沿用现有规则：不暂停当前手，超时可过牌则过牌、否则弃牌；恢复应在
席位保留窗内完成。跨手 AI 结果不能进入下一手；同手跨街可带迟到标记公开。

### 破产后的测试筹码

本轮是不可兑现测试筹码现金桌，不建设账户或买入系统。若一手结算后某席筹码为 0，该席会进入
`SIT_OUT`，不能直接 Ready。只能等本手完全结束后，由该玩家点击“补充至 200 测试筹码”；补筹金额
固定为房间起始值，不可输入自定义数额，也不会自动发生。补完仍未 Ready，玩家必须再单独点击 Ready
才能进入下一手候选。把这两次点击分开，是为了证明服务端没有把补筹偷偷当成参赛同意。

## 两好友实测清单

- [ ] 两台设备、不同网络、同一代码版本，通过同一 HTTPS 入口创建/加入；没有开放玩家入站端口。
- [ ] 各自绑定独立游戏任务，双方都看到自己连接器接入；开窗只作用于自己的席位。
- [ ] 连续完成十手，庄位/盲位/行动顺序与筹码守恒正确，双方确认能正常下注、结算和下一手。
- [ ] 至少制造一次破产：零筹码席停在 `SIT_OUT`、Ready 被阻止；仅在手间手动补至 200，补完不自动 Ready，再单独 Ready 后正常回到下一手。
- [ ] 两席各至少一次真实 `ai.start` 与合法终态，并各至少一条发生在进行中同一手、双方可见的
  真实 AI 公开气泡；只有等待区寒暄不算牌局内交流通过。可用公开聊天请求简短建议；
  沉默、迟到、跨手丢弃或失败仍如实记录，不伪造模型输出。
- [ ] 双方各测试一次 Connector 短断/恢复，确认同通知不重复唤醒；一方浏览器重连回原席。
- [ ] 页面、公开聊天与分享截图没有原生任务 ID、令牌、活动文件路径或本席秘密。
- [ ] 记录可确认的四段耗时：事件→连接器、queue→模型开始、开始→权威终态、终态→双方可见。
  无精确记录的阶段写 `unknown`；房主、好友与 Codex 的不同机器时钟不可直接相减。
- [ ] 双方给出可玩性反馈与本轮签字；在此之前不把本地测试通过标为 MVP 完成。

一个人操作两个浏览器或两台设备可以做预检，但不能替代“两名真人分别控制自己的设备、浏览器和
Codex 游戏任务”的最终签字。任何一项失败都先停止宣称通过，保留最小去敏事实后再修复；不要为了
凑满十手而跳过失败。

## 开发者的协议边界

远程只增加 `/api/model/wake/connector/poll` 和 `/ack`，使用本席模型令牌与现有合同版本校验。
长轮询以 `notification_id` / ACK 为恢复游标；线上的通知只含通知 ID 和意图 ID，固定控制提示在本机生成，
不能由远端下发任意命令文本。注册和 ACK 绑定本席授权世代，撤权后旧请求不能恢复。

连接器调用真实 Codex queue 的凭据、原生任务 ID 和工具上下文不交给牌局服务器。连接器成功 ACK
只表示本地发送器回执；模型 `ai.start`、`ai.resolve` 与公开气泡仍由原权威链路分别证明。
对应自动化在 `test/remote-wake-*.test.cjs`、`test/codex-connect.test.cjs` 与 `test/remote-beta.test.cjs`，
不调用真实模型的注入替身只能证明本地协议，不能代替本页的真人清单。
