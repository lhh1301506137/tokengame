# 德州扑克 MVP 覆盖说明

本文件回答一个具体问题：TokenGame 的好友现金桌是否遗漏了会阻断普通无限注德州扑克闭环的基础玩法。
范围是 2–4 人、不可兑现测试筹码、连续多手的私人现金桌，不声称达到赛事软件、赌场现金桌或完整扑克平台的功能面。

## 对标依据

本轮只把开源项目和公开规则当作行为参照，没有复制其源码，也没有把它们加入运行依赖：

- [PokerKit](https://github.com/uoftcprg/pokerkit)，核对提交 `54571ddda38b7da9b8c527d54c16c788ac14dac7`，MIT。它是覆盖面很广的 Python 扑克状态机与模拟库，适合做规则语义参照。
- [@hivetech/poker-engine](https://github.com/AlexAllocated/poker-engine)，核对提交 `f23776d435b66c2d23ff2c0fe95c1e69448a3865`，包版本 1.0.1，MIT，Node.js ≥22。本轮在其自身仓库实际跑过 24/24 测试，用作较接近当前技术栈的实现参照。
- [Poker TDA Rules](https://www.pokertda.com/view-poker-tda-rules/) 与 [WSOP Live Action Rules](https://www.wsop.com/pdfs/2012/2012-Live-Action-Rules.pdf) 用于核对加注重开、短额 all-in、盲注与行动语义。TDA 主要面向锦标赛，不能把其赛事管理条款整体搬进好友现金桌。

临时检出位于仓库外，不属于项目源码或交付物。

## 为什么不直接改造一个现成项目

替换引擎不能解决 TokenGame 最难的部分：逐席私有投影、唯一权威、会话 AI 授权、公开人机气泡、
迟到结果归约、远程 Connector 和宿主隔离。当前这些能力已经围绕一套很小的单手状态机形成同一产品路径；
整仓替换会把已验证边界拆散，并引入远高于补齐规则反例的迁移成本。

`boardgame.io` 是优秀的通用回合制联网框架，但不是德扑规则判定器；房间、同步和回放能力可以在公开大厅阶段
重新评估，当前接入它会与既有房间权威重复。成熟项目在本轮的价值是“告诉我们哪些行为必须证明”，不是成为新底座。

## 当前好友 MVP 覆盖

| 范围 | 当前状态 |
|---|---|
| 2–4 席私人房、按钮/大小盲与首轮/翻牌后行动顺序 | 已实现并有确定性测试 |
| fold、check、call、bet、raise、all-in 与服务端合法动作 | 已实现；无可回应对手时禁止无意义进攻动作 |
| 短额盲注、短额/累计 all-in、最小加注与行动权是否重开 | 已实现并新增成熟规则反例 |
| 翻牌、转牌、河牌、burn、无人可行动时自动 runout | 已实现 |
| 主池/边池、平分、奇数筹码、未匹配下注退款 | 已实现并有结算测试 |
| 弃牌获胜、摊牌、赢家亮牌与自愿亮牌 | 已实现 |
| 30 秒行动截止、可 check 自动 check、否则自动 fold | 已实现；不因模型或网络延长 |
| 跨手筹码、掉线原席恢复、破产 SIT_OUT（含破产后恢复） | 已实现 |
| 破产后手间固定补回 200、补筹与 Ready 分离 | 已实现并有双浏览器产品闭环 |
| 私有底牌投影、动作幂等、陈旧 revision 与越权拒绝 | 已实现并有边界/变异测试 |

规则强度补充：五张牌评估器已经穷举全部 `2,598,960` 种组合并核对标准类别分布；另有固定种子的
1,000 条合法行动序列检查终止与筹码守恒。这些是本地规则证据，不是远程真人或原生 AI 证据。

## 明确后置，不是好友 MVP 缺漏

- ante / big-blind ante、straddle、run-it-twice、bomb pot 和桌规变体；
- 可选买入、随时 top-up、cash-out、rake、钱包或任何真实价值；
- 锦标赛盲注升级、淘汰、重购、并桌与桌平衡；
- 服务重启后的牌局恢复、长期手牌历史、牌谱回放和观战系统；
- 公开大厅、账户、自动匹配、排行榜、信用和反作弊证明。

这些功能对后续公开产品可能重要，但不阻断“两名好友建房、正常打十手、双方 AI 在座位旁实时交流”的
当前闭环。下一道不可由自动化替代的门仍是两台设备、两名真人、两个独立 Codex 游戏任务的真实验收。
