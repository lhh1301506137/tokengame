# 宿主适配器合同

范围：`TG-EU-HOST-ADAPTER-CONTRACT`。实现在 `src/contract/adapter-contract.cjs`，
一致性套件在 `test-support/adapter-conformance.cjs`，参考实现与故意破坏的变体在
`test-support/adapter-simulator.cjs`。

**本文件不构成任何真实宿主门禁已通过的证据。** 真实 Gate 5（事件驱动主动唤醒）保留为
未验证，实机清单见末节。

## 为什么是两份合同

Plan Tree 里 `TG-EU-HOST-ADAPTER-CONTRACT` 写的是单数「HostAdapter 合同」，而仓库里实际
存在两个权限完全不同的面，`src/authority/host-surface.cjs` 已经把它们分开了：
`HUMAN_COMMANDS` 与 `MODEL_COMMANDS`。

合成一份的后果就是那个二分存在要否定的东西——一份平坦的适配器接口会让「把整份清单交给
模型可见的工具」成为最省事的做法，而那等于让模型替玩家下注、按 Ready、代确认隐私范围、
翻开底牌。

所以结构是：**一份共享底座 + 两份面向不同主体的合同**。共享的是「怎么说话」，
分开的是「能说什么」。

节点名与份数的偏离不由我单方面改，已列为待 Codex 裁决项（见 `REVIEW-LOG.md`）。

## 共享底座

| 部分 | 内容 |
| --- | --- |
| 版本 | `CONTRACT_VERSION = 1`。单调整数，不用 semver——兼容判断只需要「你认得我说的话吗」这一个答案，semver 的三段式会诱使人实现「minor 兼容」那套推断，而那种推断迟早会错，错的表现是一次静默的语义漂移。 |
| 信封 | 请求 `{contract_version, command, params}`；响应 `{contract_version, ok, status, result}` 或 `{contract_version, ok, status, code, details?}`。全部冻结。 |
| 错误分类 | 七类：`invalid_request` / `identity` / `state` / `quota` / `conflict` / `transport` / `contract`，加兜底 `unknown`。 |
| 身份 | 三层：`player_id` / `seat_handle` / `authority_id`。**席位凭据刻意不在里面。** |
| 生命周期 | `created → negotiated → bound ⇄ degraded → released`。`released` 是终态。 |
| 能力协商 | 适配器报它有什么，合同答每项缺失该怎么退。 |

### 错误分类为什么只有七类

仓库里此刻有 65 个错误码（`test/adapter-contract.test.cjs` 扫源码对账，漏一个就红）。
适配器不该认得全部 65 个——它需要知道的是「拿到这个码该怎么办」，而那只有七种答案。

处置表与分类表分开：处置是可以改的工程判断（比如将来给 `quota` 加退避），分类是对错误本身
的陈述。混在一起会让人以为改处置就得改分类。

两条关键处置：

- **只有 `transport` 可重试。** `state` 与 `conflict` 重发同一条命令要么无效要么危险——
  一次 `hand.act` 在 `revision_conflict` 之后重发，可能落在下一手上。
- **`state` 不当缺陷也不弹给用户。** 牌桌本来就会经过 `no_active_hand` /
  `seat_not_connected` 这些状态。弹成错误会让正常对局途中冒出一串技术文案。

未列出的码归 `unknown`，处置与缺陷相同。**默认落到最保守的一档**：新增一个码时忘了归类，
后果是它被显示出来，而不是被静默重试或被当成正常状态。

### 身份：谁持有谁不持有

这是整份合同最要紧的一句话。

| 层 | 谁持有 | 存活期 |
| --- | --- | --- |
| `player_id` | 只有真人面 | 跨手牌 |
| `seat_handle` | **只有真人面** | 直到席位释放 |
| `authority_id`（`intent_id` / `turn_id`） | 两侧 | 一次性 |

`seat_handle` 只在 `room.create` / `room.join` 的返回里产生一次，而那两条命令在真人面上。
模型能出示的只有权威自己铸造的一次性 id。

**席位凭据不在这三层里**：它不属于适配器的身份模型，只存在于协调器的托管层
（`src/host/seat-custody.cjs`）。适配器连「有一个凭据」这件事都不需要知道——写进身份模型
会让适配器作者觉得自己该管一份凭据。

### 生命周期：`released` 为什么不可逆

释放要删 web session、托管绑定与凭据。允许回头就得回答「回来时凭据从哪来」，而唯一的答案
是「适配器自己留了一份」——那正是 F6 要禁的。

另一条对称的要求：**每个状态都必须能走到 `released`**。少一条就意味着某个状态下资源清不掉。

`degraded` 不是终态。一次网络抖动让适配器再也发不出命令的话，牌局就停在那里，
而它读起来和「在等模型」分不开。

## 能力协商：这一节存在的唯一理由

两个宿主能做的事不一样，而**差异必须可检测**，不能靠试出来。

最要紧的一条是 `proactive_wake`（收到权威事件后无需玩家点击就能启动一次 follow-up）。
它在两个宿主上都还没验证过。合同的作用**不是**让它变成真的，而是让「没有这个能力」表现为
一个适配器必须声明、宿主必须据此降级的事实——而不是一次静默的不动作：牌局停在那里，
谁都不知道是在等模型还是已经死了。

| 能力 | 必需 | 任一宿主已验证 | 缺失时退到 |
| --- | --- | --- | --- |
| `command_dispatch` | 是 | 是 | 无（缺了根本没法参与） |
| `proactive_wake` | 否 | **否** | 轮询，并在 UI 上说明该席在等待唤醒 |
| `structured_ui` | 否 | 是 | 文本命令，且 `hand.act` **显式不可用** |
| `private_hand_view` | 否 | 是 | 只显示公开信息，**绝不退成给所有人看** |
| `persistent_session` | 否 | 是 | `seat.recover` |

没有降级路径的能力不该出现在这张表里：那种能力缺失时只会表现为卡住，而卡住读不出原因。

三条容易做错的降级方向，逐条写在合同的 `note` 里并由测试钉住：

- `structured_ui` 缺失时的正解是「`hand.act` 这条命令不可用」，**不是**找一条别的路把注
  下出去（章程要求真人的筹码动作由结构化控件提交）。
- `private_hand_view` 缺失时退成 `public_only`，绝不是 `everyone`。
- `persistent_session` 缺失时走 `seat.recover`，但注意保留窗只有 120 秒，而**协调器重启会
  连同凭据一起丢**，那种情况下恢复不了，按正常释放处理。

协商的四种不成立，全部当场报错而不是「差不多能用」：版本不同、角色名不认、能力名拼错、
缺必需能力。其中能力名拼错这条尤其要报错而不是忽略——忽略会让一处拼写错误表现为
「这个能力没有」，而适配器那边以为自己声明过了，两边都不会有人发现。

## 一致性套件

`runConformance(makeAdapter, { role })` 返回 `{ checks, failures, unverifiable, passed }`。

为什么必须有它：合同文件本身只是一组常量和几个纯函数，全绿也只证明「常量还在」。真正要守的
是「一个实现遵守了它」，而那必须对着实现跑。

**套件自己必须能失败。** `test-support/adapter-simulator.cjs` 里 14 项故意破坏，每项在它
适用的角色上都要让至少一条检查变红，由 `test/adapter-conformance.test.cjs` 逐个验证。少了
这一步，这套东西就是一组恒真的断言：跑得很好看，一个真问题也抓不住。

写第一版时套件自己有四处空洞，都是「一段永远走不到的检查」：

| 空洞 | 后果 |
| --- | --- |
| 读命令写死成 `view.projection` | 真人面里没有它，那一侧的信封与身份检查**整段被跳过**——而「跳过」在报告里和「通过」长得一样 |
| 释放检查跑在空状态上 | 真人面此时一张句柄都没有，于是「`handle_count` 归零」在 0 上成立，一个只写 `this.state = "released"` 的实现全绿。改成要求 `seedForRelease()` |
| 按名字前缀猜适用角色 | `release_keeps_tracked_ids` 被拿去真人面上跑，那一侧本来没有一次性 id，「没抓到」被读成「套件有洞」。改成显式声明 `roles` |
| 越界检查靠一个宽破坏抓住 | 那个变体连带破坏了释放语义，所以它是被「释放后不能再发命令」抓住的。补了一个只破坏命令面的变体 |

### `unverifiable`：套件够不到的地方

报告里第三个数组，既不是通过也不是失败。

套件查不了「无点击主动唤醒」是不是真的——它只看内部一致性。一个适配器声明
`proactive_wake` 而实际没有，一致性报告仍然全绿。所以声明该能力时，套件往
`unverifiable` 里写一条，指明这需要真实宿主实机。

**一份全绿的一致性报告不能被读成 Gate 5 通过。**

记成 `unverifiable` 而不是 `failure`：某个宿主真有这个能力时就该声明它，判成失败会逼人为了
让套件绿而少声明一项，那是更坏的结果。

## 本轮实现到哪一步

| 部分 | 状态 |
| --- | --- |
| 共享底座 | 已实现，46 条单元断言，34 条变异全杀 |
| 一致性套件 + 模拟器 | 已实现，40 条断言，14 项故意破坏逐个验证可被抓住 |
| SeatModelAdapter（模型面） | **已实现真实适配器**，`src/host/seat-model-adapter.cjs`，过一致性套件，14 条变异全杀 |
| HostCommandAdapter（真人面） | **只有合同与一致性套件，没有独立实现** |

真人面为什么没做：现有的 `src/host/table-web-host.cjs` 是浏览器宿主的协调器，它同时承担 UI
与 HTTP 服务。拆成一个独立的 HostCommandAdapter 会动到已闭合的单栈牌桌，而两份合同的节点
划分还等着 Codex 裁决。不在本轮擅自重构。

模型面那个适配器是「这份合同可实现」的唯一证据。模拟器过了只说明套件自洽——一份只有模拟器
实现的合同，整个就是本轮反复撞到的那种东西。

## 真实 Gate 5 实机清单（未执行）

**以下每一步都没有跑过。** 本环境是终端内的 Claude Code，没有桌面宿主界面，跑不了实机门禁。
清单本身是可执行的，逐步写明**是否需要用户点击**——因为「无需点击」正是被测的那个能力，
清单里任何一步偷偷依赖点击都会让门禁失去意义。

前置：`node src/run-table-core.cjs` 起权威内核，记下 origin 与令牌；宿主适配器按上表能力
声明接入。

| # | 步骤 | 需要用户点击？ | 通过判据 |
| --- | --- | --- | --- |
| 1 | 在宿主里打开牌桌界面 | **是**（打开界面本身是用户动作，不在被测范围） | 界面出现，`view.projection` 返回 200 |
| 2 | 建房，过公开范围确认门 | **是**（隐私同意必须由真人点，模型代确认时被承诺的人从未见过那句话） | 确认之前服务端一个会话都没有 |
| 3 | 第二个宿主用邀请码加入，同样过确认门 | **是** | 两席都在 `view.projection` 里 |
| 4 | 两席分别按 Ready | **是**（决定牌局什么时候开始，归真人） | 开局 |
| 5 | 第一手牌行动到某席，该席 AI 需要发言 | **否——这是被测的那一步** | 权威发出事件后，宿主在无任何用户输入的情况下启动一次 follow-up，且**恰好一次** |
| 6 | 记录 5 的实际行为 | **否** | 三种结果都要如实记：①无需点击自动启动 ②需要点击 ③既不启动也无提示 |
| 7 | 若 5 为②或③，检查降级是否生效 | **否** | UI 上必须能读出「该席在等待唤醒」，而不是静默停住 |
| 8 | 断开一侧网络 8 秒以上 | **否** | 该席进掉线与保留窗，另一侧看得见 |
| 9 | 120 秒后不恢复 | **否** | 席位释放，web session、托管绑定与凭据一并删除 |
| 10 | 关闭宿主进程再重开 | **是** | 协调器重启后凭据已丢，该席不可恢复，按正常释放处理（这是已知代价，不是缺陷） |

第 5 步与第 6 步是这份清单的全部意义。**它必须记录三种结果中实际发生的哪一种，
而不是只在成功时才记。** 第 6 步单列出来就是为了这个：一份只写「通过/不通过」的记录，
在结果为③时读起来和「还没跑」一样。

「恰好一次」也要真的数。启动两次的后果是同一席在同一个回合里发两次言，而那在权威侧会被
`seat_turn_already_active` 拒掉——看起来像没事，实际是宿主的唤醒逻辑坏了，而它只在
下一次时序更紧的时候才会表现成用户可见的问题。

第 10 步的代价说清楚：掉线恢复要覆盖的是连接断开、协调器进程还活着的情况，那条路径不受
影响。协调器重启后凭据一起丢，此时模型手上若还留着一份凭据，只可能是它先前把凭据存进了
上下文——正是 F6 要禁的那件事。所以这个「不可恢复」是设计选择，不是待修项。

## 待裁决项

2. **`src/authority/table-store.cjs` 输出的桌名**「Codex 无限注德州扑克测试桌」是用户可见串，

   并写明「本文件不改变行为，仅保留现状……收口留待 Codex 归队后处理」，所以本轮不改，

   套件各加了变异，但那是逐个加的，不是一条规则。
