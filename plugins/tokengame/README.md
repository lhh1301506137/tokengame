# TokenGame 宿主插件

这是 TokenGame 的仓库本地插件包。它让宿主里的模型以**某一席玩家的 AI**身份参与私人牌桌：
读权威裁剪后的本席上下文、发布该席的公开发言。筹码动作不在这一侧——下注、Ready、确认公开
范围、亮牌都由真人在 Web 牌桌提交。

模型能发的命令由 `src/authority/host-surface.cjs` 的 `MODEL_COMMANDS` 唯一确定，`tokengame_table`
的枚举就是它。模型**不传** `seat_id`、`seat_handle` 或任何凭据：席位身份由本机协调器在命令出
宿主之前补齐。详见 `skills/tokengame/SKILL.md`，那份文件与真实 MCP schema 由
`test/plugin-doc-schema-parity.test.cjs` 自动对账。

插件不会自动全局安装。连接文件接受本机回环 HTTP 或显式 HTTPS 根地址；协调器本身仍只监听回环。
安装后的 Hook 不会自动受信任；授予任务范围信任前应先
审阅脚本。

## 本席 AI 的私有连接

在目标Codex游戏任务中，先按项目根目录`README.md`选择本地入口或远程连接入口。真人建房或加入、确认公开范围后，在 Web
牌桌的“连接我的会话 AI”面板明确授权并下载连接文件。文件只授权本席的模型命令，不包含真人下注
凭据。不同座位分别下载，不能把文件发给朋友、贴进模型对话、提交 Git 或放入公开目录。
同一操作系统账户仍可能读取别人的本地文件；这不是操作系统账户间的安全沙箱。

模型命令经本机协调器出宿主，不直接打核心。当前项目主流程是固定服务器、热换席位连接：

```text
npm run codex:play -- "<当前 Codex 项目根的绝对路径>"       # 首选；首次若提示重启，重启后重跑同一命令
npm run connection:activate -- "<下载文件的绝对路径>"       # 每次入桌或换发，不重启 MCP
npm run connection:clear                                    # 撤销后清本地活动槽位
```

第一条只读取当前任务的`CODEX_THREAD_ID`，不会用`CODEX_SESSION_ID`比较或回退。它先只读验证项目、thread
和可信Codex可执行文件，全部通过后才更新指定项目中的TokenGame受管配置块，不改用户级配置；仓库位于
Codex项目子目录时必须传真实上层项目根。受管`cwd`使用经过canonical校验的本机仓库绝对目录；这是stdio
服务器的机器本地启动位置，不是凭据，且稳定命令输出不会回显。仓库内跟踪的`.codex/config.toml`只是
可移植模板，`cwd = "."`不代表上层项目运行配置已经加载。配置发生变化时命令只提示
重启并停止，不会同时启动beta；重启目标任务后必须重跑同一命令。配置相同也不证明工具已经加载，仍以
重启后实际发现为准。真人生成在上层Codex项目中的`.codex/config.toml`会包含本机目录布局，不要分享或
提交Git；仓库随源码跟踪的可移植模板不在此列。`codex:play`仅在Windows无显式可执行文件时使用受限可信PATH解析；非Windows必须
显式提供可执行文件。激活把验证后的完整文件发布到 Git 忽略的
`.tokengame-private/active-model-connection.json`，发布失败保留旧文件。源下载不会自动删除，真人应在
确认成功后自行安全删除。激活与清除都不是 MCP 工具，模型不能替真人执行授权选择。

页面「撤销」负责服务端吊销，`connection:clear` 只负责本地槽位；两者不能互相代替。当前宿主没有向
stdio 调用提供可验证的任务身份，因此同一项目内仍应只在专用游戏任务使用，不宣传为密码学任务隔离。

`codex:play`把通知目标固定在服务端。固定模式页面不会填写、显示或提交任务UUID，只显示
`target_configured`对应的人话状态；旧手填UUID只保留给自定义queue兼容。它不会自动开启通知窗，每个窗口
仍须本人重新确认。启动beta后，应先结束当前Codex回复并让这个固定游戏任务保持空闲，再在牌桌开窗；任务正在
运行时，通知可能已接收却不能并发形成新模型回合或权威结清。“已接收”不是AI完成。直接`npm run beta`
是高级手工兼容入口，默认没有Codex通知发送器；需要通知时须显式
提供`TOKENGAME_CODEX_WAKE`、绝对`TOKENGAME_CODEX_EXECUTABLE`、`TOKENGAME_CODEX_CWD`和
`TOKENGAME_CODEX_THREAD`，不会从PATH猜测。

稳定 launcher 内部仍用以下变量；手工注册或兼容排障时才需要直接配置：

| 变量 | 用法 | 说明 |
| --- | --- | --- |
| `TOKENGAME_MODEL_CONNECTION_FILE` | 稳定 launcher 内部/手工入口 | 本席连接文件的绝对路径。MCP 每次请求读取它；路径或内容无效会明确失败，不退回其他身份。 |
| `TOKENGAME_MODEL_TOKEN` | 高级兼容入口 | 不使用连接文件时才手动提供本席令牌。旧进程级令牌已不能用于模型操作。不要把令牌交给模型填写。 |
| `TOKENGAME_TABLE_ORIGIN` | 可选 | 连接文件已有地址，通常不必设置；显式值与文件不同会拒绝。只用令牌时默认 `http://127.0.0.1:7802`。 |
| `TOKENGAME_PUBLIC_ORIGIN` | beta 启动入口 | 已由真人在进程外准备的规范 HTTPS 根 origin；用于页面入口和下载文件，不改变协调器的回环监听。 |

`TOKENGAME_COMMAND_ORIGIN` 与 `TOKENGAME_AUTHORITY_TOKEN` 是协调器连核心的配置，不是此
MCP 进程的配置。模型工具参数不接收这些令牌，也不接收真人席位凭据。

换一份新授权会使旧文件失效；同一下载请求可安全重试。每个 Web 会话最多登记 128 个不同授权
请求，已生效的同一请求可重下。刷新页面或短断恢复不撤销绑定；主动撤销、离桌或席位释放会使旧
权限失效。撤销不能回滚已经交给核心处理的请求。文件持有者可读取本席底牌并公开发言，真人应
审阅自己 AI 的行为。`host_seen` 只表示收到过有效请求，不表示宿主持续在线。

默认入口仍是本机回环地址，不要把 `127.0.0.1` 当成异地邀请链接。显式配置
`TOKENGAME_PUBLIC_ORIGIN` 后，浏览器入口与下载的本席连接文件可使用由真人自行提供的 HTTPS 根
origin；协调器仍只监听回环，项目不提供或绑定特定隧道服务。

## 连接好友已有的远程牌桌

房主使用 `npm run beta:remote -- "<真人提供的HTTPS根地址>"`。每位玩家独立配置自己的项目、激活自己下载的
连接文件，再在专用 Codex 游戏任务运行 `npm run codex:connect -- "<自己的Codex项目根>"`。
**不要在好友电脑运行 `codex:play` 来加入远程房间**，那是另起本地服务。

从旧版升级后，即使配置未变，也需手动重启 Codex 一次，让运行中的 MCP 进程载入新版代码。
后续仅入桌、换发或清除连接文件不需要重启；连接文件热切换不等于代码热更新。

本机 Connector 只接收本席的通知 ID / 意图 ID，并将固定控制提示交给本机 Codex 发送器；远端只见不透明
目标别名。ACK 丢失只重发同一 ACK，不重发 queue；换发连接文件或撤权会停止旧连接器。连接器不设置
模型与强度，不接收任意远程控制文本，不领取牌局意图，不替真人下注，也不自动开启模型通知窗口。

每位玩家仍必须结束当前启动回复、保持自己的游戏任务空闲，并在 Web 配置中心明确开启有限窗口。
完整操作、安全边界与十手真人清单见 [两好友远程内测](../../docs/REMOTE-FRIEND-MVP.md)。
**两台设备、两个真实 AI 的好友回路尚未验证；本地协议测试不能证明该端到端结果。**

## 历史实现：A/B/C/D 显式公开桥

早期版本以 `$tokengame public <message>` 这类前缀标记赛时提示，由同步 `UserPromptSubmit` Hook
在模型生成前登记，行动在 A/B/C/D 四个固定身份的 Web 牌桌里提交。那条路径已不是产品路径，
保留说明见 `skills/tokengame/SKILL.md` 末尾一节。

旧探针记录见 `docs/HOST-PROBE-CHECKLIST.md`、`docs/ACCEPTANCE-EVIDENCE.md` 与
`docs/MULTIPLAYER-VERTICAL-SLICE.md`。当时捆绑 MCP 没有获得 Hook 的 `PLUGIN_DATA`，因此
pending 文件即时归档有生命周期限制；该记录不能直接当成新宿主或新路径的能力判断。
